1. What is CSS Specificity?

CSS Specificity is the algorithm browsers use to decide which CSS rule applies to an HTML element when multiple rules target the exact same element with conflicting properties.

Example

p { color: blue; }         /* Element selector */
.text { color: green; }    /* Class selector */
#demo-1 { color: red; }    /* ID selector */

Explanation: Even though p and .text match the element, the ID selector (#demo-1) has the highest specificity weight and wins.

2. CSS Specificity Formula (A - B - C - D)

Specificity is calculated across four distinct columns. Always compare from left to right.

Column Selector Category Example Score
A Inline Styles style="color: red" 1-0-0-0
B ID Selectors #header 0-1-0-0
C Classes, Attributes, Pseudo-classes .box, [type="text"], :hover 0-0-1-0
D Elements, Pseudo-elements div, p, ::before 0-0-0-1

3. Quick Specificity Estimator

Type a selector (such as div.card .title:hover or #nav .item a) to estimate its B-C-D counts.

0 A: Inline
0 B: IDs
2 C: Classes / Attr / Pseudo
1 D: Elements

4. Specificity Ranking Chart

From lowest to highest specificity in standard cascade order:

Rank Selector Type A-B-C-D Notes
1 (Lowest) Universal * & combinators (>, +, ~) 0-0-0-0 Combinators themselves add zero specificity.
2 Type / element & pseudo-element (::after) 0-0-0-1 Each matching tag or pseudo-element adds 1 in column D.
3 Class, attribute selector, or pseudo-class (:focus) 0-0-1-0 Each adds 1 in column C.
4 ID selector (#main) 0-1-0-0 Each adds 1 in column B.
5 (Highest Normal) Inline style attribute 1-0-0-0 Applies directly to the element's style attribute.

5. Combined Selectors

When chaining selectors together, count every matching token in its corresponding column:

ul#nav li.active a { }   /* 0-1-1-2: 1 ID, 1 class, 2 elements */
article.post > p:first-child { } /* 0-0-2-2: 2 classes/pseudo-classes, 2 elements */
input[type="email"].field { }    /* 0-0-2-1: 1 attr + 1 class = 2 in C, 1 element */
Tip: Combinators like > (child), + (adjacent sibling), and ~ (general sibling) organize relationships—they do not add weight on their own.

6. Practical Component Example

Suppose a card heading has a base class, a featured variant, and an ID wrapper:

.card-title { color: #2563eb; }             /* 0-0-1-0 */
.featured .card-title { color: #059669; }   /* 0-0-2-0 */
#special-card .card-title { color: #dc2626; } /* 0-1-1-0 */

7. Special Functional Selectors: :where(), :is() & :not()

  • :where(...) always contributes 0 specificity—great for resets and base defaults you want easy to override.
  • :is(...) takes the specificity of its most specific argument.
  • :not(...) takes the specificity of its most specific argument (it does not add weight by itself).
:where(.card h2) { color: gray; }      /* 0-0-0-0 */
:is(.card, #hero) h2 { color: navy; } /* 0-1-0-1 (because #hero is inside :is()) */

8. Cascade Order & Source Order

When two rules have the exact same specificity, the rule that appears later in the cascade wins.

.demo .equal-text { color: #2563eb; }       /* 0-0-2-0 — earlier */
.demo .equal-text.later { color: #dc2626; } /* 0-0-3-0 — higher specificity & later */

9. Practical Rules to Remember

Keep specificity low: Prefer clean class names over chained IDs or deep descendant paths so styles are easy to override later.
Avoid overusing !important: It overrides normal specificity and makes debugging cascading conflicts much harder.

10. Interview Q&A

Q1: Do ten class selectors (.a.b.c.d.e.f.g.h.i.j) beat one ID selector (#unique)?
No. Specificity columns do not roll over into higher columns—0-1-0-0 beats 0-0-10-0.
Q2: Why is :where() useful in component libraries?
Because :where() has zero specificity, consumers can override default styles with a simple class or element selector without fighting specificity wars.
Q3: What happens when two rules have identical specificity?
The browser checks origin/importance and cascade layers first, and if still tied, the rule declared later in source order wins.
